# بنية المشروع

## مسار الإنتاج

- `backend_server.py`: نقطة تشغيل محرك Python الموحد فقط.
- `platform_core/`: المصادقة، الإعدادات، السجل، Ollama، التعلّم، المعاينة والتكاملات المشتركة.
- `flowscope/`: محللات تدفقات الشبكة وأحداث ADS وتقاريرها.
- `threatscope/`: محللات XDR والبصمات الرقمية وتقاريرها.
- `gateway/`: بوابة Node.js للمصادقة والصلاحيات والتوجيه وسجل طلبات API.
- `frontend/`: واجهة Next.js الوحيدة للمستخدم.
- `scripts/`: أدوات مساندة تستدعيها المنصة، مثل تحويل Word إلى PDF.
- `data/`: قوالب الإدخال والتقارير المطلوبة وقت التشغيل.
- `storage/`: إعدادات وبيانات تشغيل محلية حساسة، ويشمل `runtime/` لمعرّفات العمليات و`logs/` لسجلات الخدمات، ولا تُحزم مع المصدر العام.

## ملفات التشغيل

- `platform_launcher.py`: المشغّل الفعلي متعدد الأنظمة؛ يكتشف OS والمعمارية ويدير الاعتماديات والبناء والعمليات والشبكة.
- `start.cmd` و`stop.cmd`: واجهة Windows المعتادة.
- `start_nextjs.ps1` و`stop.ps1`: واجهة PowerShell للتوافق مع الاستدعاءات السابقة.
- `start.sh` و`stop.sh`: واجهة Linux/Ubuntu.
- `scripts/verify_portability.py`: فحص الجهاز والاعتماديات وسلسلة الاتصال على النظامين.

## ملفات غير إنتاجية

- `tests/`: اختبارات Python المشتركة.
- `artifacts/`: حزم التوزيع والعينات وسجلات التشغيل القديمة؛ راجع `artifacts/README.md`.
- `archive/`: كود قديم أو تجريبي معزول عن التشغيل، ومخصص للمراجعة والحذف لاحقًا.
- `tmp/`: ملفات مؤقتة ومعاينات مولدة يمكن إعادة إنشائها.
